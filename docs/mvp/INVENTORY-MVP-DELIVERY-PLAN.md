**Costing rules (owner-mandated, unchanged):** exactly one of `LOT_ACTUAL` (FEFO for expiry items, FIFO fallback) or `WEIGHTED_AVERAGE` per company; no default; chosen in the Setup Wizard; **permanently locked** on confirmation; never mixed across branches or products of a company; negative stock refused; sale deduction, COGS and journal commit in the **same transaction** (CLAUDE.md rules 18, 25, 29).

**Offline boundary (approved, Rule 31 / ARCHITECTURE §offline):** online-only for every financial or inventory-changing action. The PWA may cache UI and read-only reference data for temporary network loss. Hard-blocked offline ("Class C"): any stock / reservation write, sales on tracked items, provider payments, refunds, credit, adjustments, receiving, Z finalize, role / secret changes, online-order actions. With real stock, **every tracked sale deducts stock, so it is Class C**; Class B could only ever cover untracked items and needs its own approved conflict / numbering / reservation / idempotency / reconciliation model. **Unresolved decisions:** O-1 does the owner want Class B at all in v1 (recommend: no); O-2 offline receipt numbering and the paper-log fallback procedure; O-3 what the POS shows when the API is unreachable (recommend: read-only catalogue + clear "sales paused" state).

## 6. First independently safe task — implemented (I-1)

`apps/api/src/modules/stock/company-costing.repository.ts` + `company-costing.integration.test.ts` (inert: no route, module or sale path imports it).

- `lockCostingMethod(tx, {tenantId, companyId, method, userId})`: only the two approved methods (anything else rejected before the database); `SELECT … FOR UPDATE` on the company row serialises confirmations; first confirmation sets method + time + user; same method again is a no-op (original time and user kept); the other method → `409 COSTING_METHOD_LOCKED`; the conditional `UPDATE … WHERE lockedAt IS NULL` and the DRAFT-H trigger are backstops.
- `requireLockedCostingMethod(tx, {tenantId, companyId})`: the single source every stock operation will use; no locked method → `409 INVENTORY_NOT_ENABLED`; a chosen-but-unconfirmed method is not usable.
- Evidence: 9/9 real-PostgreSQL tests as the application role through `runScoped` (RLS in force), including a forced overlap (the rival blocks on the row lock, then gets 409), 20 parallel confirmations with both methods (exactly one wins), cross-tenant → 404, sibling company independent; mutants: dropping `FOR UPDATE` + the guard is caught by 2 tests, treating an unconfirmed method as usable is caught, re-locking on re-confirm is caught (dropping `FOR UPDATE` alone is equivalent: the guard still protects — defence in depth). Strategy / engine unit tests still 38/38; tsc, ESLint and prettier clean.
- Not done, by design: the migration is **not applied**; the route (`DRAFT-H-costing-method.controller.ts.txt`) is still a draft because it needs the new permission + S0b entry.
