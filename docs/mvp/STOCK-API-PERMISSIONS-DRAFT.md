**Not routes, by design:** BOM consumption and its cancellation (`consumeBuildToOrder`, `cancelBuildToOrder`) are called only from the sale transaction, which is the frozen complete-sale — there is **no HTTP endpoint that consumes components**. The reconciliation **job** is not a route.

## 2. Isolation rules enforced on every route (rule 5, 6, 7)

Tenant from the authenticated session only; company derived server-side from the validated branch; branch from the validated route param and the session's branch scope (`@ScopedParam`) — never from a body, query or header field; all reads and writes run in the RLS-scoped transaction (FORCE RLS tenant + branch on every stock table; tenant on the recipe tables). The services refuse a branch that is not the company's (`404 STOCK_SCOPE_NOT_FOUND`) and read another tenant's rows as nothing; this is proven for every service in its integration test (cross-tenant, cross-company, cross-branch, branch-narrowed session).

## 3. Audit and errors (to implement with the routes)

Audit actions (non-secret): `stock.document_posted`, `stock.adjustment_posted`, `stock.count_posted`, `inventory.costing_locked` (security-relevant), `recipe.published`. Stable error codes already produced by the services: `INVENTORY_NOT_ENABLED` 409, `INSUFFICIENT_STOCK` 409, `STOCK_NOT_TRACKED` 409, `IDEMPOTENCY_CONFLICT` 409, `GAIN_VALUATION_NOT_APPROVED` 409, `APPROVER_MUST_DIFFER` 409, `COSTING_METHOD_LOCKED` 409, `STOCK_SCOPE_NOT_FOUND` 404, `RECIPE_NOT_FOUND` 409, `RECIPE_VARIANT_NOT_BOM` 409, validation 422s.
