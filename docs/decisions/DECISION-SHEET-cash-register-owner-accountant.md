# DECISION SHEET — the minimum the owner and the accountant must decide to unblock the cash-register features

- **Status:** **FOR DECISION. Nothing here is approved or implemented.** Prepared 2026-11-13 from the verified Phase 4 cash-register backend (uncommitted, `fwt\p4`).
- **Read with:** [PROPOSAL-cash-register-open-decisions.md](PROPOSAL-cash-register-open-decisions.md) (full blocker analysis), [ADR-0021](ADR-0021.md), [ADR-0022](ADR-0022.md), `docs/architecture/ARCHITECTURE.md` §F.5–F.7.
- **How to answer:** write the option letter next to each decision (or "other: …"). The **recommended** option is marked ★. A decision marked _migration_ means its answer needs a database migration that this work was forbidden to create.

## 0. What is already true (so nobody has to decide it again)

- Open / Count / Close / Read work end to end on the device-bound session and are tested on real PostgreSQL + Redis. The opening float is **GL-neutral** and counted **once** (it is the ledger's first row; the session's float column is a copy that is never added).
- A **close needs a count equal to the ledger**; any difference is refused and the session stays open (interim, fail-closed).
- Nothing posts to the general ledger, and no cash movement other than the single `OPENING_FLOAT` row is written.
- The `cash_register:*` keys cannot be granted to any role yet, so the routes are **inert in production** until decision **E-1** is made.
