# ADR-0004 — Defence in depth for isolation: app-layer scoping + RLS backstop + CI probe suites

- **Status:** Accepted (2026-09-03, with Z-1)
- **Related:** architecture §46; [`../architecture/SECURITY.md`](../architecture/SECURITY.md); [ADR-0003](ADR-0003.md), [ADR-0010](ADR-0010.md)

## Context

A multi-tenant commerce + financial platform where a single cross-tenant or
cross-branch leak is catastrophic (financial data, customer PII, secrets). No single
mechanism is trusted.

## Decision

Three independent layers, each capable of stopping a leak on its own, plus an
automated attacker:

1. **Application layer (primary).** `tenant_id` / `branch_id` flow **only** from the
   authenticated session into an immutable `RequestContext`. Reading a scope value
   from a request body / param / header / query / realtime subscription string is a
   **banned pattern** — a custom ESLint rule plus a probe test. All scoped data
   access goes through `ScopedRepository`, which injects the tenant + branch filter;
   **raw Prisma/model access is ESLint-forbidden in scoped modules**
   (`no-raw-prisma-in-scoped-modules`). Every controller route declares
   `@RequirePermission(...)` or `@Public()` — a route with neither **fails lint**
   (`route-must-declare-permission`).
2. **Database layer (backstop).** RLS on **every** tenant-owned table
   (`tenant_id = current_setting('app.tenant_id')::uuid`). The app connects as a
   non-superuser, non-`BYPASSRLS` role. `SET LOCAL app.tenant_id` is set inside every
   request transaction. Platform operations use a separate, audited path.
3. **CI probe suites (verification).** For every endpoint, authenticate as tenant B
   / branch Y and attempt to read or mutate tenant A / branch X resources by id,
   param, URL and document id → expect 403/404. **Build-blocking.** A branch-isolation
   suite does the same across branches; a register-isolation suite covers financial
   rows.

The three custom lint rules and the probe-suite harness are scaffolded in **Phase 0**
(Tasks 0.2 and 0.11) with negative-test fixtures that must fail.

## Consequences

- **Positive:** a missed `ScopedRepository` call is caught by RLS; a missed RLS
  policy is caught by the probe suite; a new endpoint without a permission decorator
  fails lint before review.
- **Negative:** RLS + connection pooling needs care (see ADR-0010 and the Phase 0
  spike); every scoped query must run inside a transaction that sets the GUC.
- **Cost:** the probe suite grows with the endpoint count; accepted as the price of
  the guarantee.
