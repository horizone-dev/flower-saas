# ADR-0007 — Provider adapter ports; all raw external secrets are Platform Super Admin only

- **Status:** Accepted (2026-09-03, Z-4 + V3 requirements revision)
- **Related:** architecture §37–39, §42–43; [`../architecture/SECURITY.md`](../architecture/SECURITY.md); [ADR-0012](ADR-0012.md)

## Context

Flower SaaS integrates payment providers, an LLM provider, a WhatsApp BSP and an
SMS/OTP vendor. GCC vendor availability, pricing and compliance vary and are not yet
decided. The V3 revision hard-requires that **no tenant-realm user** may ever hold
a raw external credential.

## Decision

**Adapter ports now, vendor selection later:**

- `PaymentProvider` (`createIntent · authorize · capture · refund · getStatus ·
verifyWebhook`), `AiProvider`, WhatsApp BSP port, SMS/OTP port,
  `EInvoicingProvider` (ADR-0012), storage port, notifications port. Adapters live
  in isolated directories, registered in a provider registry. **No core business
  logic references a concrete vendor.**
- Actual vendor selection is deferred to the relevant implementation phase
  (payments/GL: Phase 3; AI/WhatsApp: Phase 9), evaluating GCC support, pricing,
  compliance and ops.

**Secrets — strict rule:**

- Only **Platform Super Admin** can create, view, edit, rotate or revoke a raw
  external API credential. **The capability does not exist in the tenant realm** —
  there is no tenant-side permission key for secrets.
- `provider_credential(id, tenant_id, company_id?, branch_id?, provider, mode
(TEST|LIVE), secret_blob_ref (KMS), non_secret_config, status, version,
updated_by, updated_at)` — a dedicated Super-Admin-only service with its own audit
  stream. Branch-level credentials: Super Admin configures each
  `(tenant, company, branch)` tuple; a bulk/templated screen keeps it manageable.
- KMS envelope encryption (per-tenant DEK); decrypted server-side inside the owning
  module for one call; masked in every UI (`••••4242`); **never logged** (redaction
  filter + tests); versioned; revocable.
- Tenant users manage only **non-secret operational settings** (which methods to
  display, min/max amount, whether the AI may create orders, greeting text, hours,
  handoff rules) — stored in separate columns/rows, never adjacent to a secret.

## Consequences

- **Positive:** the core is vendor-agnostic; a vendor swap is an adapter change;
  the blast radius of a credential compromise is confined to the platform console
  (hardened per SECURITY.md — separate realm, hardware MFA, IP allowlist,
  dual-control).
- **Negative:** onboarding friction — a tenant cannot self-serve payment setup.
  Mitigated by an onboarding checklist, a bulk config screen, and clear "provider
  not configured for this branch" states in the tenant UI (§R.9).
