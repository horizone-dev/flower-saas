# ADR-0015 — Auth primitives: hashing, tokens, sessions (Phase 1 task 1.5)

- **Status:** Accepted (2026-09-03, Phase 1 task 1.5)
- **Related:** [`../architecture/SECURITY.md`](../architecture/SECURITY.md) "Auth
  primitives", [`../phase-1/PHASE-1-PLAN.md`](../phase-1/PHASE-1-PLAN.md) §0 (OD1–OD3),
  §4 (OI1, OI4)

## Decisions

### Password hashing — Argon2id (OI1)

`@node-rs/argon2` (prebuilt Rust binaries — no node-gyp), default algorithm
Argon2id, parameters **m = 19 456 KiB (19 MiB), t = 2, p = 1** (the OWASP
minimum). A login for a non-existent user still runs `verify` against a fixed
dummy digest — no user-enumeration timing oracle. Revisit the cost once the CI
runner's p95 for a `hash` call is measured; raise `t`/`m` if headroom allows.

### Access tokens — HS256 JWT, realm-scoped (OD1)

`jose`, HS256, `AUTH_JWT_SECRET` (≥ 32 chars; the dev default is refused when
`NODE_ENV=production`). TTL **600 s**. Claims: `sub`, `sid`, `aud` (`tenant` /
`platform`), `typ: access`, `tid` (tenant realm). The **audience separates the
two realms** — a tenant token fails `jwtVerify({ audience: 'platform' })` and
vice-versa. The token carries no permissions; the server-side session is the
authority and the revocation point.

### Sessions — Redis, server-authoritative

`SessionData` in Redis (`flower:session:{id}`), TTL = the session's remaining
life (`AUTH_SESSION_TTL_SECONDS`, default 12 h). Revocation writes a 60 s
tombstone then the key expires — `AuthGuard` sees "not found" on the **next
request** (hard gate G6). The resolved access snapshot (permissions + scope +
entitlements, from `PolicyService`) is computed at login / token-refresh and
cached on the session; a role/scope change takes effect on the next refresh.

An immutable `session` row is also written to Postgres (via the platform path) as
the audit trail; Redis is authoritative for liveness.

### Refresh tokens — rotating, family reuse-detection

Opaque 32-byte tokens, SHA-256 at rest, **Redis-only in Phase 1**
(`flower:refresh:{hash}` + `flower:refresh-family:{familyId}`). One login = one
family. Every `/auth/refresh` marks the old token `used` (kept 120 s) and issues
a new one in the same family. Replaying a `used` token ⇒ **reuse**: the whole
family and its sessions are revoked, a `REFRESH_REUSE` security event is written,
and the caller gets 401 `REFRESH_REUSED`. A Redis flush therefore forces every
session to re-authenticate — fail-closed and acceptable. The `refresh_token`
Postgres table is reserved for the durable history a later phase may want.

### Brute-force lockout

Per-identity counter (`workspace/email` or `platform/email`) locks at
`AUTH_LOGIN_MAX_ATTEMPTS` (default 5); per-IP counter locks at 20× that (one IP
legitimately serves many users, including behind the app's own proxy). A success
clears the identity counter; both decay on `AUTH_LOGIN_LOCKOUT_SECONDS` TTL
(default 900 s). A locked login returns 429 `LOGIN_LOCKED`.

### MFA — TOTP only (OD2)

`otplib`, RFC 6238. Tenant users may enrol (`/auth/mfa/enrol` → `/mfa/confirm`);
**platform accounts must have a confirmed TOTP factor** to log in. A 5-minute
signed MFA-challenge token bridges the password step and the code step. Step-up
(`/auth/step-up`) re-asserts TOTP and sets `mfaLevel = STEP_UP` for
`AUTH_STEP_UP_TTL_SECONDS` (default 300 s). WebAuthn is a later, separate factor
in the same model.

### Set-password — admin-generated links (OD3)

`/auth/set-password` consumes a single-use `set_password_token` (SHA-256 at rest,
short TTL). No email is sent in Phase 1 — the raw link is returned to the admin
that created the user (task 1.7 / 1.9). Self-service email reset waits for the
notifications phase.

## Consequences

- The whole auth surface is exercised by one Testcontainers integration test
  (Postgres + Redis): login → `/me/access` → refresh rotation → reuse → family
  revoke → lockout → logout → session dead.
- `LOG_LEVEL=silent` in the api vitest config keeps 4xx warn lines out of test
  output.
