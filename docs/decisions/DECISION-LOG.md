## Financial-design decisions (ZF-1 … ZF-9) — all APPROVED 2026-09-03

| #        | Decision                                                                                                                                                                                                                                             | Resolution / rationale                                                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ZF-1** | Real double-entry general ledger (Chart of Accounts + balanced journals) as the financial source-of-truth projection — vs a lighter single-entry ledger.                                                                                             | **Approve the double-entry GL.** It is the only design that structurally prevents double-counting and supports a real P&L / VAT return. See [ADR-0005](ADR-0005.md). |
| **ZF-2** | GL posting timing — synchronous, inside the operational transaction, for core events; async via outbox only for rollups and period jobs.                                                                                                             | **Approve.** Core postings are deterministic; inline keeps the GL and the drawer from ever diverging.                                                                |
| **ZF-3** | Ledger scope — one GL per _company_ (legal entity / VAT registration), with branch / POS / shift as journal-line dimensions; tenant consolidation is a reporting rollup — vs a ledger per branch.                                                    | **Approve one GL per company, dimensioned.**                                                                                                                         |
| **ZF-4** | Z-Report numbering — gapless `z_number` per register/session, with a separate number series for the optional branch business-day close.                                                                                                              | **Approve.**                                                                                                                                                         |
| **ZF-5** | Branch business-day close (level B) — mandatory, optional-per-tenant, or deferred?                                                                                                                                                                   | Per-shift Z-Report is **mandatory from Phase 4**; branch business-day close is **optional per tenant** and lands in **Phase 10**.                                    |
| **ZF-6** | Accounting periods — monthly soft-close with a permissioned, audited back-posting / adjustment path.                                                                                                                                                 | **Approve** (light implementation).                                                                                                                                  |
| **ZF-7** | Discounts & returns booked as _contra-revenue_ (gross sales, discounts, net sales all visible) — vs net-only.                                                                                                                                        | **Approve contra-revenue.**                                                                                                                                          |
| **ZF-8** | COGS / inventory valuation method — perpetual weighted-average — vs periodic.                                                                                                                                                                        | **Approve perpetual weighted-average.**                                                                                                                              |
| **ZF-9** | Accounting scope at launch — build the double-entry foundation so a balance sheet is _possible_, but ship management P&L + VAT return + AR/AP + cash/Z first; full statutory statements + external accounting-package sync are Phase 10 / class C–D. | **Approve.** This is a florist commerce + operations platform with a solid internal ledger, not a replacement for the tenant's audit accountant.                     |
