# ADR-0008 — Financial and inventory-changing sales are online-only for v1

- **Status:** Accepted (2026-09-03, Z-6)
- **Related:** architecture §51; [ADR-0005](ADR-0005.md)

## Context

A truly offline POS must solve concurrent-sale conflict resolution, gapless invoice
numbering across a partition, stock reservation without the server, idempotent
replay, and financial reconciliation. Getting any of these subtly wrong corrupts
inventory or the ledger.

## Decision

- **First production release: financial and inventory-changing sales are
  online-only.** The POS PWA degrades on connection loss to **read-mostly + a small
  set of provably-safe queued actions**, with a loud banner and a visible queue.
- **Class A (safe offline):** attendance punches; draft carts + hold/resume;
  quotation creation (no stock/payment effect); driver POD photo + status; viewing
  cached catalog / prices / own schedule. Ordered IndexedDB queue replayed with an
  `Idempotency-Key`; the server assigns authoritative numbers; clock-offset
  correction.
- **Class B (conditionally safe):** a _cash-only, no-credit, no-loyalty_ walk-in
  sale of **STOCKED** items (never BOM or custom) against cached price/tax — **only
  if the tenant enables `pos.offline_cash_sale`**, which stays **architecture-ready
  but unimplemented** until its conflict / numbering / reservation / idempotency /
  reconciliation model is **separately approved and tested**.
- **Class C (online-only, hard-blocked):** any inventory or reservation write; BOM /
  custom-bouquet sales; card / wallet / provider payments; refunds; voids of synced
  sales; credit & advance; gift-card / loyalty; adjustments / transfers / counts;
  receiving; Z-report finalize; device activation; role / permission / user / secret
  changes; reading another branch's data; anything money-moving in the ledger;
  online-order actions.
- **No full-offline claim is made** in marketing or docs (§R.6).

## Consequences

- **Positive:** the ledger and inventory can never be corrupted by an offline
  partition in v1; the reconnect story is "replay Class A in order, server is
  authoritative, conflicts surface for a human."
- **Negative:** a genuine internet outage stops sales at a branch. Accepted for v1;
  Class B is the escape hatch once its model is approved.
