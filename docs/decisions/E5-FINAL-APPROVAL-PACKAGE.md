## 2. Unresolved policies (separate — not defaulted silently)

1. **Terminal selection (E5-O5).** Default = the completing terminal. The open question for the owner: an order created on terminal A and
   completed on terminal B — confirm the cash belongs to B's drawer (recommended; it is where the money is physically taken), or require
   the completing terminal to equal the order's origin terminal (stricter, would refuse cross-terminal completion).
2. **Counting-time policy (E5-O4 / S-2).** While a session is `COUNTING` the default refuses new cash. Unresolved: whether a cashier may
   keep selling during a count and how a late sale is re-counted. Not invented here; refusal is the safe default.

## 3. What each approval unlocks

Approvals O1/O2/O3/O5/O7 are required to apply the patch. O4 and O6 only set values. Applying the patch with the policy `OFF` changes no
behaviour; **a second explicit owner decision is required to flip the policy**, after provisioning, permission enablement and staging
reconciliation (§6).

## 6. Smallest implementation sequence

1. Owner decisions E5-O1…O8 (§1), including the two unresolved policies (§2).
2. **Independent** accountant sign-off (§5.1) and **independent** security sign-off (§5.2). The author may not sign.
3. Apply the approved wiring patch **and** the pin-amendment patch together (policy stays `OFF`); no migration.
4. Run the final local regression (typecheck, ESLint, build, Prettier, DB/RLS, full API in memory-limited sequential batches, mutation).
5. Commit and verify CI on the final commit (a separate explicit instruction is needed to commit).
6. Complete register provisioning and permission enablement (the cash-register permissions are still policy-disabled; the earlier decision
   sheet's migrations/answers apply).
7. Staging: run real cash sales, split sales and refunds; run `reconcileSession` and `reconcileBranchWindow`; every session must be
   consistent and every window free of `MISSING_MOVEMENT`/`ORPHAN_MOVEMENT`/`AMOUNT_MISMATCH` for the cut-over scope.
8. Only then, a separate owner decision flips `CASH_SALES_POLICY` to the approved mode. Rollback = set it back to `OFF` (no data change);
   the drawer rows already written are sealed records and stay.
