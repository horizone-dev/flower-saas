# ADR-0006 — Money as integer minor units + currency code + exponent

- **Status:** Accepted (2026-09-03, carried from v0.1; reaffirmed)
- **Related:** architecture §42, §45; `packages/money`; [ADR-0005](ADR-0005.md)

## Context

The GCC uses **3-decimal currencies** (KWD, BHD, OMR) alongside 2-decimal ones (AED,
SAR, QAR) and 0-decimal contexts. A 2-decimal assumption anywhere is a defect.
Binary floating point cannot represent decimal currency amounts exactly.

## Decision

- Money is stored as **`amount_minor BIGINT` + `currency_code` (ISO 4217) +
  `currency_exponent`** (0, 2 or 3). `100.500 KWD` → `amount_minor = 100500`,
  `currency_code = 'KWD'`, `currency_exponent = 3`.
- **All monetary arithmetic goes through `packages/money`** — a pure value object
  with a currency/exponent table, minor-unit math, explicit rounding rules
  (half-up by default, configurable), and a documented residual-allocation rule for
  splitting (the residual goes to the first / largest allocation deterministically).
- **`NUMERIC` is allowed only in derived reporting columns**, never in an
  operational money column.
- **No binary floating point anywhere** in a money path — ESLint discourages `number`
  arithmetic on money-typed values; code review enforces it.
- Multi-currency: the GL is kept in the company's base currency; foreign
  transactions store the transaction currency + rate; an `FX_GAIN_LOSS` account
  absorbs differences.
- `packages/money` gets its **first real test suite in Phase 0 Task 0.3** — AED 2dp
  and KWD 3dp rounding, split/partial residual allocation.

## Consequences

- **Positive:** exact arithmetic; 3-decimal currencies are first-class; one place to
  audit all rounding.
- **Negative:** every amount that crosses a boundary (API, DB, UI) carries three
  fields, not one — modelled as a `Money` DTO in `packages/shared-types`.

## Alternatives considered

- **`NUMERIC`/`DECIMAL` columns** — rejected as the operational representation: JS
  has no native decimal; every read/write needs a wrapper anyway, and integer minor
  units are unambiguous across languages and wire formats.
- **A decimal library everywhere** — rejected: heavier, and still needs the
  currency/exponent metadata that the value object carries.
