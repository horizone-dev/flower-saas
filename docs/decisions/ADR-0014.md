# ADR-0014 — Phase 1 RLS enforcement: roles, the platform path, and uuidv7()

- **Status:** Accepted (2026-09-03, Phase 1 task 1.1)
- **Related:** [ADR-0010](ADR-0010.md) (RLS spike verdict), [ADR-0004] (RLS
  requirement), [`../architecture/SECURITY.md`](../architecture/SECURITY.md),
  [`../conventions/DB-CONVENTIONS.md`](../conventions/DB-CONVENTIONS.md),
  `packages/db/prisma/migrations/*_phase_1_identity_tenancy_rbac`

## Context

ADR-0010 proved the scoped-transaction + `SET LOCAL app.tenant_id` pattern works
under PgBouncer. Phase 1 turns it into real schema. Three questions had to be
settled to write the first migration:

1. **What DB roles exist, and can any of them bypass RLS?** SECURITY.md says the
   app connects as "a non-superuser, non-BYPASSRLS role" and that "platform
   operations use a separate, explicitly audited connection/path" — but does not
   say whether that separate path uses `BYPASSRLS` or per-table permissive
   policies.
2. **How does a legitimately cross-tenant platform read work** (Super Admin
   listing every tenant; the audit viewer; provisioning; impersonation setup)?
3. **UUID v7 PKs on Postgres 17**, which has no built-in `uuidv7()` (that arrives
   in PG 18).

## Decision

### 1. Three DB roles

| Role              | Attributes                         | Used by                                                             |
| ----------------- | ---------------------------------- | ------------------------------------------------------------------- |
| `flower_app`      | `NOSUPERUSER NOBYPASSRLS`          | every tenant-scoped request. RLS always applies.                    |
| `flower_platform` | `NOSUPERUSER **BYPASSRLS**`        | the platform module's `PlatformRepository` only — the audited path. |
| `flower_migrate`  | `NOSUPERUSER NOBYPASSRLS CREATEDB` | DDL / `prisma migrate deploy` (owns the objects in prod).           |

`flower_app` additionally has **no DB privilege at all** on the platform identity
realm tables (`platform_user`, `platform_credential`, `platform_role`,
`platform_session`, …) and only `SELECT` (not write) on the platform-global
reference tables (`plan`, `plan_version`, `entitlement_default`, `limit_default`,
`permission_registry`). This is defence in depth on top of the application-layer
realm separation (distinct token audience + session namespace).

### 2. The cross-tenant platform path uses `BYPASSRLS`, and is audited in code

`flower_platform` is `BYPASSRLS`. The alternative — a permissive
`OR current_setting('app.is_platform', true) = 'on'` branch on **every** RLS
policy — was rejected: it makes every policy longer, is easy to get subtly wrong
(a missed table becomes a silent cross-tenant hole), and moves a security-critical
decision into 24 copy-pasted policy expressions.

Instead:

- `BYPASSRLS` is confined to **one** connection pool, used by **one** repository
  class (`PlatformRepository`, Phase 1 task 1.2), reachable only from the
  `platform` module (lint-enforced like `ScopedRepository`).
- Every call through it writes an `audit_log` row (Phase 1 task 1.14), so a
  cross-tenant read is always attributable.
- The tenant realm has no code path and no DB grant that reaches this pool.

RLS remains the **backstop** for the tenant realm (a missed `ScopedRepository`
call fails closed); the probe suite (task 1.13) is the backstop for a missed
policy.

### 3. `uuidv7()` is a pure-SQL function created by the first Phase 1 migration

```sql
CREATE OR REPLACE FUNCTION uuidv7() RETURNS uuid AS $$
  SELECT encode(
    set_bit(set_bit(
      overlay(uuid_send(gen_random_uuid())
              placing substring(int8send((extract(epoch FROM clock_timestamp())*1000)::bigint) FROM 3)
              FROM 1 FOR 6),
      52, 1), 53, 1), 'hex')::uuid;
$$ LANGUAGE sql VOLATILE;
```

First 48 bits = unix-ms timestamp; version nibble forced to `0b0111`; the rest is
`gen_random_uuid()` entropy (built in since PG 13). Models use
`@default(dbgenerated("uuidv7()"))`. When the deployment target reaches PG 18 the
function can be redefined as a thin wrapper over the built-in, or dropped and the
defaults repointed — a mechanical migration, no data change.

## Consequences

- One simple RLS policy shape everywhere:
  `USING (tenant_id = nullif(current_setting('app.tenant_id', true), '')::uuid)`
  `WITH CHECK (…)` — an unset GUC yields zero rows (fails closed).
- `audit_log` / `outbox` are range-partitioned; RLS on the partitioned parent is
  enforced for access through the parent (verified in
  `packages/db/test/migration.test.ts`).
- A compromise of the `flower_platform` credential is a full cross-tenant breach —
  it is treated with the same care as a superuser credential (separate secret,
  not in the app's env, rotated on the platform-secrets schedule).
- The RLS spike's `spike_app` role (ADR-0010) is superseded by `flower_app`.
