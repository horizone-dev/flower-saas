# ADR-0011 — UAE primary region, region-portable, KSA-data-residency-ready

- **Status:** Accepted (2026-09-03, Z-3)
- **Related:** architecture §R.3, §45, §50; [ADR-0012](ADR-0012.md)

## Context

KSA PDPL and cloud-computing rules may require in-country hosting for some tenant
data; UAE PDPL applies to UAE tenants. A launch region must be chosen without
hardcoding the platform to it.

## Decision

- **The initial primary deployment is UAE-region infrastructure.**
- **The code stays region-agnostic.** `tenant.region` is a first-class attribute.
  No region name, endpoint, bucket or law is hardcoded into core logic. Object
  storage, KMS, mail and provider endpoints are configuration.
- The architecture stays **KSA-data-residency-ready**: a second region /
  data-boundary deployment is a Terraform + configuration exercise, planned but not
  built now (warm-standby / secondary-region plan in §50).
- **Before onboarding a KSA tenant to production:** verify the then-current KSA
  data-residency / cloud-compliance requirements for the target operating model,
  and stand up a KSA deployment / data boundary if required. This is a gate on KSA
  go-live, tracked alongside ADR-0012 (ZATCA).

## Consequences

- **Positive:** one region to operate at launch; no premature multi-region cost;
  the door to KSA residency is kept open by design.
- **Negative:** a KSA tenant with a strict in-country requirement cannot be
  onboarded until the second region exists — an accepted, explicit gate, not a
  surprise.
